# shared-service-oauth (`inventaris`)

[Bahasa Indonesia](README.md)

An example NICE SharedService in `nice_token` mode with the slug `inventaris`, written in Go (`net/http`) with the reference library `nice/pkg/nicetoken`. Clients call this service directly with a NICE access token; NICE is not on the request path. The service verifies the token itself according to the [token verification contract](../../nice/docs/token-verification.md), keeps data apart per organization, and checks sensitive operations online with NICE.

Tested against nice revision: `c7a5086` (2026-11-13)

## Contents

| File | Contents |
|---|---|
| `main.go` | `nicetoken` wiring (`New`, `Run`, `StartFeed`), document-level swag annotations including `x-nice-roles` |
| `routes.go` | the single route table (method, path, permission, sensitive) and the `CORS -> mux` handler chain |
| `items.go` | item handlers, validation, error shape, per-operation swag annotations |
| `store.go` | in-memory item store per organization |
| `config.go` | reads the environment and `.env` |
| `cors.go` | CORS for registered SPAs |
| `docs/swagger.json` | Swagger 2.0 generated by `make swag`, embedded and served at `/openapi.json` |
| `scripts/smoke.sh` | smoke test against a NICE that has been set up |

## Operations

| Operation | Permission | Sensitive |
|---|---|---|
| `GET /items` | `inventaris.items.read` | |
| `GET /items/{id}` | `inventaris.items.read` | |
| `POST /items` | `inventaris.items.create` | |
| `PUT /items/{id}` | `inventaris.items.edit` | |
| `DELETE /items/{id}` | `inventaris.items.delete` | yes, checked online with NICE |

`GET /healthz` and `GET /openapi.json` are open without a token and are not in the OpenAPI document. After the import, the NICE catalog has the roles `inventaris.viewer` (read), `inventaris.admin` (every permission), and `inventaris.operator` (read, create, edit; from `x-nice-roles`).

Item body: `{"name": "...", "quantity": 0}`. `name` is 1 to 120 characters after trimming surrounding spaces, `quantity` is an integer of at least 0. Application errors use the same shape as `nicetoken`: `{"error": "...", "error_description": "..."}`, e.g. `400 {"error":"invalid_argument","error_description":"name"}` and `404 {"error":"not_found"}`.

Behavior worth knowing:

- The tenant is `nice_org_id` from the verified token, never a header, parameter, or body. An organization that calls for the first time gets a tenant at once (`ProvisionOnFirstUse`). Data lives in memory only and is lost when the service stops.
- A copy of the JWKS is kept at `JWKS_FILE`, so a service that restarts while NICE is down still verifies tokens that have not expired.
- Without `NICE_SERVICE_API_KEY`, the service still runs and logs a warning at start: the access change feed is off (revocation takes effect only when the token expires, at most 30 minutes) and `DELETE /items/{id}` answers `503`.

## Prerequisites

- Directory layout: the `replace github.com/nice-platform/nice => ../../nice` in `go.mod` only works when the `nice` repository sits next to `example/`:

  ```text
  <parent>/
    nice/
    example/
      shared-service-oauth/
  ```

- Go 1.27, `curl`, `jq`, and `openssl` (for `nice/scripts/dev-token.sh`).
- A dev NICE running, at `http://localhost:8080` by default (`cd ../../nice && make db && make migrate && make dev`). NICE at another address works too: put it in `NICE_ISSUER` in `.env` and in `NICE` in the checklist shell.

## Configuration

Copy `.env.example` to `.env`. The service reads `.env` from the directory it runs in; a variable set in the environment wins over the file.

| Variable | Default | Meaning |
|---|---|---|
| `NICE_ISSUER` | required | the NICE issuer, exactly as the `iss` claim of its tokens. Without it the service stops with a message naming `NICE_ISSUER` |
| `LISTEN_ADDR` | `127.0.0.1:8081` | listen address |
| `JWKS_FILE` | `data/jwks.json` | JWKS copy on disk (`data/` is not committed) |
| `CORS_ALLOWED_ORIGINS` | `http://localhost:5180` | browser origins allowed to call, comma separated |
| `NICE_SERVICE_API_KEY` | empty | API key of a platform Service Account with the `nice.service` role (step 9); turns on the feed and the online check |
| `SMOKE_SA_ID`, `SMOKE_API_KEY` | empty | read only by `scripts/smoke.sh`: a tenant Service Account and its API key (step 10) |

## Run and test

```bash
make run          # go run . on 127.0.0.1:8081
make test         # unit tests; no NICE needed (tokens signed in the tests, static JWKS, fake checker)
make swag         # regenerate docs/swagger.json from the annotations
make swag-check   # fails when docs/swagger.json differs from a fresh swag run
scripts/smoke.sh  # needs a NICE set up with the checklist below
```

If the `go` on your `PATH` does not match `GOROOT`, call `make GO=/path/to/go test`.

`TestOpenAPIMatchesTheRouteTable` compares the route table in `routes.go` with the embedded `docs/swagger.json`: permission and sensitive mark must match, and the document must declare no other operation. After changing an annotation, run `make swag` and commit the result.

## NICE setup checklist

Run from the `example/shared-service-oauth` directory. Console steps name the page; the `curl` snippets are the equivalent.

First, prepare shell variables. Tokens come from `nice/scripts/dev-token.sh` (client `nice-console` with the NICE dev default redirect `http://localhost:5173/callback`; if the account uses two-step verification, set `TOTP_SECRET`, see the script header). Tokens last 30 minutes; repeat when they expire.

```bash
export NICE=${NICE:-http://localhost:8080}   # address of NICE, same as NICE_ISSUER in .env; dev-token.sh reads it too

# your dev Platform Admin account
read -rp 'Platform Admin email: ' ADMIN_EMAIL; read -rsp 'Password: ' ADMIN_PASSWORD; echo
ADMIN_TOKEN=$(../../nice/scripts/dev-token.sh "$ADMIN_EMAIL" "$ADMIN_PASSWORD"); unset ADMIN_PASSWORD

# your dev tenant organization owner account
read -rp 'Tenant owner email: ' OWNER_EMAIL; read -rsp 'Password: ' OWNER_PASSWORD; echo
OWNER_TOKEN=$(../../nice/scripts/dev-token.sh "$OWNER_EMAIL" "$OWNER_PASSWORD"); unset OWNER_PASSWORD

ORG_ID=$(curl -sS "$NICE/api/v1/me/organization" -H "Authorization: Bearer $OWNER_TOKEN" | jq -r .organization.id)
curl -sS "$NICE/api/v1/organizations/$ORG_ID/projects" -H "Authorization: Bearer $OWNER_TOKEN" | jq '.projects[] | {id, name}'
PROJECT_ID=prj_...   # the tenant project that will use inventaris
USER_ID=$(curl -sS "$NICE/api/v1/me/profile" -H "Authorization: Bearer $OWNER_TOKEN" | jq -r .profile.user_id)
```

### 1. NICE environment

Add to `nice/.env`, then restart NICE. Without these NICE refuses `http` endpoints and loopback addresses.

```text
NICE_OUTBOUND_ALLOW_HTTP=true
NICE_OUTBOUND_ALLOW_CIDRS=127.0.0.0/8
```

`NICE_OUTBOUND_ALLOW_CIDRS` is a comma-separated list of CIDRs. The SPA origin `http://localhost:5180` in `NICE_CORS_ALLOWED_ORIGINS` (e.g. `http://localhost:5173,http://localhost:5180`) is only needed by the `public-client-pkce` example, not by this service.

### 2. Run the service

```bash
cp .env.example .env
make run
curl -sS http://127.0.0.1:8081/healthz
```

Leave it running in another terminal. The keys in `.env` are filled in at steps 9 and 10.

### 3. Register `inventaris`

Console: Platform Admin, **Shared Service**, **Daftarkan Shared Service**. Write the endpoint as `http://127.0.0.1:8081`, not `localhost`, so NICE never tries `::1`. `auth_mode` need not be sent; its default is `nice_token`.

```bash
curl -sS "$NICE/api/v1/shared-services" -X POST \
  -H "Authorization: Bearer $ADMIN_TOKEN" -H 'Content-Type: application/json' \
  -d '{"slug":"inventaris","name":"Inventaris","endpoint":"http://127.0.0.1:8081","health_path":"/healthz"}'
```

### 4. Import `/openapi.json`

Console: the `inventaris` detail page under **Shared Service**, catalog import (preview, then apply).

```bash
DOCUMENT=$(curl -sS http://127.0.0.1:8081/openapi.json | jq -Rs .)
PREVIEW=$(curl -sS "$NICE/api/v1/shared-services/inventaris/catalog-imports" -X POST \
  -H "Authorization: Bearer $ADMIN_TOKEN" -H 'Content-Type: application/json' \
  -d "{\"document\":$DOCUMENT}")
printf '%s' "$PREVIEW" | jq '{added: [.diff.added[] | {key, permission, sensitive}], roles: [.diff.roles[] | .key]}'
IMPORT_ID=$(printf '%s' "$PREVIEW" | jq -r .import_id)
HASH=$(printf '%s' "$PREVIEW" | jq -r .hash)
curl -sS "$NICE/api/v1/shared-services/inventaris/catalog-imports/$IMPORT_ID/apply" -X POST \
  -H "Authorization: Bearer $ADMIN_TOKEN" -H 'Content-Type: application/json' \
  -d "{\"hash\":\"$HASH\"}"
```

The preview must show five operations, four permissions (`deleteItem` sensitive), and the roles `inventaris.viewer`, `inventaris.admin`, and `inventaris.operator`.

### 5. Activate the service

```bash
curl -sS "$NICE/api/v1/shared-services/inventaris/activate" -X POST -H "Authorization: Bearer $ADMIN_TOKEN"
```

### 6. Organization entitlement

Console: Platform Admin, **Organisasi**, the tenant organization detail page.

```bash
curl -sS "$NICE/api/v1/organizations/$ORG_ID/entitlements" -X POST \
  -H "Authorization: Bearer $ADMIN_TOKEN" -H 'Content-Type: application/json' -d '{"service":"inventaris"}'
```

### 7. Activate in the project

Console: tenant project, **Product & Activation**.

```bash
curl -sS "$NICE/api/v1/projects/$PROJECT_ID/services/inventaris/activation" -X PUT -H "Authorization: Bearer $OWNER_TOKEN"
```

### 8. Bind a user to an inventaris role

Console: tenant project, **IAM**. IAM copies the catalog and the activation asynchronously: if the answer is `unknown_role` or `service_not_active`, wait a few seconds and retry. `echo "$BINDING_ID"` must print `rb_...`, not `null`.

```bash
BINDING_ID=$(curl -sS "$NICE/api/v1/projects/$PROJECT_ID/role-bindings" -X POST \
  -H "Authorization: Bearer $OWNER_TOKEN" -H 'Content-Type: application/json' \
  -d "{\"principal_type\":\"PRINCIPAL_TYPE_USER\",\"principal_id\":\"$USER_ID\",\"role\":\"inventaris.operator\"}" | jq -r .role_binding.id)
```

`inventaris.operator` does not hold `inventaris.items.delete`; use `inventaris.admin` to try deleting items.

### 9. Platform Service Account with `nice.service` (feed and online check)

The Platform Admin creates a Service Account in a project of the platform organization (create the project if there is none), gives it the `nice.service` role, then an API key with `allowed_services` holding `nice`. Console: **Service Account** in the platform organization project, then **Pengguna platform** for the `nice.service` role.

```bash
PLATFORM_ORG_ID=$(curl -sS "$NICE/api/v1/me/organization" -H "Authorization: Bearer $ADMIN_TOKEN" | jq -r .organization.id)
PLATFORM_PROJECT_ID=$(curl -sS "$NICE/api/v1/organizations/$PLATFORM_ORG_ID/projects" -X POST \
  -H "Authorization: Bearer $ADMIN_TOKEN" -H 'Content-Type: application/json' \
  -d '{"slug":"service-readers","name":"Service readers"}' | jq -r .project.id)
FEED_SA_ID=$(curl -sS "$NICE/api/v1/projects/$PLATFORM_PROJECT_ID/service-accounts" -X POST \
  -H "Authorization: Bearer $ADMIN_TOKEN" -H 'Content-Type: application/json' \
  -d '{"name":"inventaris-feed","description":"Access change feed and online check for inventaris"}' | jq -r .service_account.id)
curl -sS "$NICE/api/v1/admin/role-bindings" -X POST \
  -H "Authorization: Bearer $ADMIN_TOKEN" -H 'Content-Type: application/json' \
  -d "{\"principal_type\":\"PRINCIPAL_TYPE_SERVICE_ACCOUNT\",\"principal_id\":\"$FEED_SA_ID\",\"role\":\"nice.service\"}"
curl -sS "$NICE/api/v1/projects/$PLATFORM_PROJECT_ID/api-keys" -X POST \
  -H "Authorization: Bearer $ADMIN_TOKEN" -H 'Content-Type: application/json' \
  -d "{\"service_account_id\":\"$FEED_SA_ID\",\"name\":\"inventaris-feed\",\"allowed_services\":[\"nice\"]}" | jq -r .key
```

The key is shown once. Put it in `NICE_SERVICE_API_KEY` in `.env`, then restart `make run`; the feed warning at start is gone.

IAM learns about a new Service Account asynchronously, so a binding made right after creating it can be answered 400 `principal_not_in_org`. Wait a few seconds and repeat the binding; the same holds for step 10.

### 10. Tenant Service Account for the smoke test

Console: tenant project, **Service Account** (account and API key) and **IAM** (binding).

```bash
SMOKE_SA_ID=$(curl -sS "$NICE/api/v1/projects/$PROJECT_ID/service-accounts" -X POST \
  -H "Authorization: Bearer $OWNER_TOKEN" -H 'Content-Type: application/json' \
  -d '{"name":"inventaris-smoke"}' | jq -r .service_account.id)
curl -sS "$NICE/api/v1/projects/$PROJECT_ID/role-bindings" -X POST \
  -H "Authorization: Bearer $OWNER_TOKEN" -H 'Content-Type: application/json' \
  -d "{\"principal_type\":\"PRINCIPAL_TYPE_SERVICE_ACCOUNT\",\"principal_id\":\"$SMOKE_SA_ID\",\"role\":\"inventaris.viewer\"}"
curl -sS "$NICE/api/v1/projects/$PROJECT_ID/api-keys" -X POST \
  -H "Authorization: Bearer $OWNER_TOKEN" -H 'Content-Type: application/json' \
  -d "{\"service_account_id\":\"$SMOKE_SA_ID\",\"name\":\"inventaris-smoke\",\"allowed_services\":[\"inventaris\"]}" | jq -r .key
echo "$SMOKE_SA_ID"
```

Put the Service Account id in `SMOKE_SA_ID` and the key in `SMOKE_API_KEY` in `.env`.

### 11. Smoke

```bash
scripts/smoke.sh
```

The script reads only `.env`, never prints a key or a token, and checks: NICE answers, `/healthz` answers, `GET /items` without a token is answered `401 missing_token`, a Service Account token is issued through `client_credentials` with the scope `nice:aud:inventaris` (`client_id` is the Service Account id, `client_secret` the API key), and `GET /items` with that token is answered `200`. It exits with code 0 when everything passes. Failures point to checklist steps:

| Answer | Step likely missed |
|---|---|
| no `.env`, NICE or service unreachable | 2 (and NICE must be running) |
| `invalid_client` | 10: the Service Account id does not own the key, the key is revoked or expired, the account is disabled |
| `invalid_scope` | 3 to 7, or 10 (`allowed_services` must hold `inventaris`) |
| `403 permission_denied` from the service | 10: binding of the Service Account to an inventaris role |

## Revocation test (optional)

Needs `NICE_SERVICE_API_KEY` set (step 9). A user token issued before the binding is revoked is refused with `401 token_stale`.

```bash
read -rsp 'Owner password: ' OWNER_PASSWORD; echo
USER_TOKEN=$(../../nice/scripts/dev-token.sh "$OWNER_EMAIL" "$OWNER_PASSWORD" "" "openid nice:aud:inventaris nice:prj:$PROJECT_ID"); unset OWNER_PASSWORD
curl -sS http://127.0.0.1:8081/items -H "Authorization: Bearer $USER_TOKEN"     # 200
sleep 2
curl -sS -X DELETE "$NICE/api/v1/projects/$PROJECT_ID/role-bindings/$BINDING_ID" -H "Authorization: Bearer $OWNER_TOKEN"
sleep 2
curl -sS http://127.0.0.1:8081/items -H "Authorization: Bearer $USER_TOKEN"     # 401 token_stale
```

The pause before revoking is needed because the feed works at one-second resolution: a token issued in the same second as the revocation is not caught.
